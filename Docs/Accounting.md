# Bitcoin Ledger V1 计算规则

这些规则是账本格式的一部分。所有页面、编辑、删除及备份恢复都使用同一个 `LedgerEngine` 从完整历史重新计算。账户余额不是可手工修改的第二份事实。

## 1. 精度、时间与范围

- BTC 数量使用 `Int64` 存储 satoshi，1 BTC = 100,000,000 satoshi。最低支持 1 satoshi；不经过 `Double`。
- 人民币本金及人民币手续费最多 2 位小数；历史 BTC/CNY 价格最多 8 位小数。全部使用 Foundation `Decimal`，JSON 用普通十进制字符串保存，避免其他 JSON 工具将金额转成二进制浮点数。
- 费用人民币等值、成本分摊及比率保留 12 位小数，使用银行家舍入（恰好中点时取偶数）。界面可显示 2 位人民币小数，但不会将显示结果写回账本。
- 单条 BTC 数量、任一账户及所有账户的当前 BTC 总量不能超过 21,000,000 BTC。单条人民币金额不超过 10^15 元，单个 BTC 价格不超过 10^12 元。累计 satoshi 运算检查整数溢出；累计人民币运算检查 Decimal 精度及溢出。
- 重算顺序为日期时间升序 → `sequence` 升序 → UUID 字符串升序。同一时间的记录因此有稳定顺序；备份保留 sequence。日期须为有限值，sequence 范围为 0 至 Int64.max−1。
- 每笔完成时，每个账户都必须非负。新增、编辑或删除导致任何历史时点透支时，拒绝整个修改。

## 2. 输入的准确含义

### 买入

`amountCNY` 是购买 BTC 的人民币本金，不含单独填写的人民币手续费。`amountSats` 是**实际到账的净 BTC**。

- 人民币收费：现金总支出 = 本金 + 人民币手续费；账户增加实际到账 BTC。
- BTC 收费：手续费视为从本次购买的 BTC 中扣除。购买毛数量 = 实际到账 BTC + BTC 手续费；账户只增加实际到账 BTC。人民币本金已经覆盖毛数量，不能再将 BTC 费用人民币等值加到成本。
- 如果手续费从原有余额另行扣除，应将买入按实际获得 BTC 记录，再单独添加一笔 BTC 费用；不要把这种情况填成买入内扣费用。

### 内部转账

`amountSats` 是来源账户的**总扣款**，`receivedSats` 是目标账户实际到账量。

```text
来源账户变化 = −转出总额
目标账户变化 = +实际到账
BTC 手续费 = 转出总额 − 实际到账
全账户 BTC 变化 = −BTC 手续费
```

例：Binance 扣 0.00100000 BTC，Green Wallet 收到 0.00099800 BTC，BTC 总量只减少 0.00000200 BTC（200 satoshi）。

转账本金不是买入或卖出，不增加累计购买数量、人民币投入或已实现盈亏，也不移除原有成本。BTC 手续费造成的损耗由剩余 BTC 承担，因此持仓总成本不变、每 BTC 实际成本上升。

如果手续费在外部用人民币支付，可记录零 BTC 差额的转账及人民币手续费。转账本金仍不增加投入；额外人民币费用属于新的现金支出，并计入持仓成本。一条记录只允许一种手续费币种；同时发生两种费用时，另一种用独立费用记录。

### 卖出／消费

`amountSats` 是卖出的 BTC 本金，不含额外 BTC 手续费。`amountCNY` 是**扣完人民币卖出手续费后实际收到的净人民币**。

- 账户扣减 = 卖出 BTC + 额外 BTC 手续费。
- 填写的人民币卖出手续费只用于费用统计，不从净实收再扣一次，也不增加累计人民币投入。
- 支付商品或其他 BTC 消费可用卖出记录，人民币实收填 0，备注记录用途；会按成本确认处置损失，不记录商品价值。
- 不管理卖出所得人民币余额。

### 独立费用

- BTC 费用：必须选择付款账户，扣 BTC 数量。还有 BTC 时保留剩余持仓总成本；最后的 BTC 全被费用耗尽时，全部剩余成本转为已实现损失，持仓成本归零。
- 人民币费用：增加累计人民币投入。持有 BTC 时资本化进持仓成本；没有 BTC 时记为已实现费用损失。
- 分类有交易、提币、链上转账、其他；分类不改变金额计算。

## 3. 费用原值与人民币快照

每笔 BTC 费用同时保留：

- `feeSats`：原始 BTC 费用，整数 satoshi；`feeBTC = feeSats ÷ 100,000,000`，可无损得到原始 BTC 数值。
- `feePriceCNY`：发生费用时采用的 BTC/CNY 价格，必须大于 0。
- `feeCNYEquivalent`：`feeBTC × feePriceCNY`，12 位银行家舍入后的人民币等值，作为十进制字符串明确写入 JSON；恢复时必须与前两项计算一致。

后来的实时行情不会改写历史价格或费用等值。没有历史行情服务自动核定历史费用价格；录入者需要确认当时使用的价格。0 手续费的快照价格必须为 0；人民币费用不带 BTC 数量或 BTC 换算价格。

## 4. Dashboard 指标

| 指标 | 定义 |
|---|---|
| 累计人民币投入 | 所有买入本金 + 买入、转账、独立费用中的外付人民币费用；卖出不冲减本指标，卖出净实收中已经扣除的人民币手续费不再加入 |
| 累计购买 BTC | 所有买入毛数量之和，包括从当次购买中内扣的 BTC 手续费；不包含内部转账 |
| 当前 BTC | 所有账户当前 satoshi 余额之和 |
| 平均买入价格 | 累计买入人民币本金 ÷ 累计购买毛 BTC；排除手续费，终身累计指标 |
| 总成本／持仓成本 | 当前尚未处置 BTC 的剩余成本；不是累计投入，也不是累计投入减卖出收入 |
| 实际成本价 | 当前持仓成本 ÷ 当前 BTC；包含资本化人民币费用及留在成本中的 BTC 损耗 |
| 累计手续费人民币价值 | 每笔人民币费用 + 每笔 BTC 费用发生时的人民币等值 |
| 累计消耗 BTC | 所有买入内扣、转账、卖出附加、独立费用的 feeSats 之和；卖出的本金不属于手续费 |
| 手续费占累计投入比例 | 累计手续费人民币价值 ÷ 累计人民币投入 |
| 当前总价值 | 当前 BTC × 最近一次成功取得的 BTC/CNY 价格 |
| 未实现盈亏 | 当前总价值 − 当前持仓成本 |
| 收益率 | 未实现盈亏 ÷ 当前持仓成本 |

分母为 0 时比率及单位成本没有定义，显示「—」，不显示 0%、NaN 或无限大。没有可用行情时，不伪造当前价值或盈亏；网络失败时保留最后成功价格及其时间。

## 5. 卖出采用全账户移动加权平均成本

本人全部账户视作一个成本池，不按账户分别计算成本，不使用 FIFO。每次卖出之前：

```text
处置 BTC = 卖出本金 BTC + 附加 BTC 手续费
处置成本 = 卖出前持仓成本 × 处置 BTC ÷ 卖出前 BTC 总量
剩余成本 = 原持仓成本 − 处置成本
本笔已实现盈亏 = 实收净人民币 − 处置成本
```

处置成本舍入到 12 位，余额保留减法后的残差。全数卖出时直接移除全部剩余成本，避免残留分摊误差。已实现盈亏与未实现盈亏独立；BTC 转账及独立 BTC 费用不会凭行情价格创造已实现收益。

这是个人管理账口径。V1 不提供税务批次、税单或复杂税务计算。

## 6. 修改与备份

- 编辑及删除提交前重算整个候选历史；成功后一次性保存。失败不修改原有账本。
- 删除账户只适用于余额为零的账户。已有历史引用时逻辑删除（`isArchived = true`），从日常账户列表及新增记录选择器隐藏，同时在历史和备份保留账户身份；没有历史时可直接删除。已删除账户不能有非零余额。活动账户名称不区分大小写且不能重复，删除后的旧名称可以重新使用。
- JSON 是完整可恢复备份，含版本、账户、全部交易原值、费用快照及稳定排序字段。恢复校验全部记录后再替换账本。
- CSV 是便于查看及迁移的交易历史导出；JSON 是 V1 的恢复格式。
- 核心单元测试使用合成数据，覆盖买入、转账、卖出、费用、修改、删除、账户守恒、成本、盈亏、费用比例、1 satoshi、过量精度、非法备份金额和手续费快照不一致。
