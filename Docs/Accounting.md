# 计算与迁移

## 记录与汇率

购买保存原人民币投入、到账 BTC、账户和时间。人民币投入除以购买时已可用的 USD/CNY 参考汇率（每美元人民币数），得到美元投入；同时保存汇率、参考日期与来源。修改金额或时间时重新换算，只修改 BTC、账户或备注则沿用原汇率。行情刷新不重估投入。

汇率来自 ECB 每日数据，经 Frankfurter 获取。为避免使用尚未公布的数据，从参考日之后的 UTC 午夜起采用；休市日取此前最近的值，参考日期最多早七天。它不是银行成交汇率。新购买换算失败时保留草稿，不保存记录；旧购买缺可靠汇率时保留 BTC 和人民币原值，对应时点的美元总成本、每 BTC 成本与盈亏显示「—」。

转移从来源扣除转出量，向目标加入到账量；两者差额为损耗，不增加投入。到账不能超过转出，来源与目标不能相同，任何历史时点的来源余额都不能不足。

## 指标

```text
每笔美元投入 = 人民币投入 ÷ 已保存汇率（每美元人民币数）
总成本 = 所有购买的美元投入之和
累计损耗 BTC = 所有转移的（转出量 − 到账量）之和
总持有 BTC = 所有购买的到账量之和 − 累计损耗 = 各账户余额之和
每 BTC 成本 = 总成本 ÷ 总持有 BTC
当前市值 = 总持有 BTC × BTC 美元市价
浮盈 = 当前市值 − 总成本
浮盈率 = 浮盈 ÷ 总成本 × 100%
损耗占比 = 累计损耗 BTC ÷ 总持有 BTC × 100%
```

总览「总成本」是实际投入美元总额；图中成本线是每 BTC 成本。转移损耗减少持有量，因此每 BTC 成本上升，总成本不变。零持有时每 BTC 成本和损耗占比未定义，零投入时浮盈率未定义，均显示「—」；损耗占比允许超过 100%。

BTC 使用 Int64 satoshi（1 BTC = 100,000,000 satoshi），金额与汇率使用 Decimal，美元换算保留十二位小数。JSON 使用十进制字符串，显示舍入不改存储值。记录按时间、sequence、UUID 重放；历史状态只纳入截止时刻已发生的事件。编辑、删除和导入都验证完整历史。

## 迁移与保护

当前 schema 7 使用美元，另保存以首笔购买时刻为锚点的每日结算行情依据。schema 1–6 升级保留已有资料；schema 6 的中午价格只有对应同一已结束分钟时才能复用，不把不同时间的价格改名作为新目标。schema 5 保留全部账户、记录、购买汇率、美元行情与迁移报告，新增的每日行情初始为空；schema 4 保留原 ID、时间、账户、BTC 和人民币金额，可靠历史汇率全部取得后一次提交换算，失败不丢原值。旧人民币行情缓存弃用，不能改标签作为美元行情。

## 每日盈亏

从第一笔购买所在的北京时间自然日起，采用该笔购买的时分秒（包括存储的分数秒），每天生成一个结算目标。第一天的目标就是首笔购买时刻；持仓与成本只纳入该时刻及此前的事件，未来的结算目标不提前生成。列表显示时分，存在秒值时显示时分秒。

固定市场价使用 Coinbase BTC-USD 结算前最后已结束一分钟的收盘参考价。例如结算为 11:00:17 时，使用 10:59–11:00 的完整分钟，不使用尚未结束的 11:00–11:01。市值 = 当时持仓 × 该价格；盈亏 = 市值 − 当时本金；盈亏率 = 盈亏 ÷ 当时本金。零持仓不依赖行情，零本金不定义盈亏率。缺少指定分钟价或可靠购买汇率时，不借用邻近价格或未来资料。

每日市场价格依据随 JSON 完整备份保存。交易补录、更正和删除后，历史会计金额由更正后的账本重算；更正或删除首笔购买使锚点改变时，重选每日结算时刻并补齐对应行情，旧价格只有对应同一已结束分钟时才复用。顶部当前估算与每日固定记录独立，估值不扣额外卖出费用。

成本数字是否标色直接来自购买记账：购买事件在上一条结算之后、本条结算及此前时，由本条首次纳入成本；首条包含首笔购买。该日成本数字按本期购买投入的红绿规则显示，未发生购买的日期保留普通颜色，转移不触发标色。结算后发生的购买在下一条记录首次计入，删除购买后相应标色同步取消。成本或汇率未知时显示灰色「—」，零变动保留普通颜色；市值、盈亏和盈亏率沿用各自原有显示规则。

schema 1–3 只在迁移时读取：

- 原人民币购买保留净到账 BTC，投入为 `amountCNY + feeCNY`，不重复扣 BTC 费用。
- 原转移保留来源、目标、转出与到账；无法归属购买的额外成本进入报告。
- 只有起始中间余额为零、无卖出或调整干扰的一对一资金链可合并为购买。非末尾链必须用尽；末尾唯一购买的剩余中间资金计入该笔成本。
- 多笔资金、分批购买、卖出、独立费用、余额调整或来源不明等歧义进入报告，不猜数据或后续转移来源。可靠账户映射及必要旧账户保留。

读取旧账本不立即改写。首次保存前保留原始字节到 `ledger.before-upgrade-vN-UUID.json`；导入也保留来源和被替换账本。读取失败不以空账本覆盖原文件，外部修改冲突拒绝覆盖。JSON 用于完整恢复，CSV 用于查看。
