# 计算与迁移

## 两类事件与美元口径

购买保存原始人民币实际投入 `amountCNY`、实际到账 BTC `receivedSats`、账户及原始时间（界面输入到分钟）。后台将该笔人民币除以购买时已经可用的 USD/CNY 历史参考汇率，固定保存 `conversion.amountUSD`、汇率、参考日期与来源。编辑人民币金额或时间时重新换算；只修改 BTC、账户或备注沿用该笔汇率。行情刷新不会重估投入。

参考汇率使用 ECB 每日数据，保守地在参考日之后的 UTC 午夜起使用；休市日取此前最近已可用的值，最多七天。它不是购买当时的银行成交汇率。无法取得可靠汇率时不猜：旧 BTC / 人民币记录保留，美元投入、成本及盈亏显示「—」；新购买保留草稿并提示换算失败。

转移从来源扣除 `amountSats`，向目标加入 `receivedSats`，损耗为二者之差；不增加美元投入。到账不得超过转出，账户不能相同，历史来源余额不得不足。

```text
每笔美元投入 = 原人民币投入 / 该笔已保存的历史 CNY/USD 汇率
累计投入美元 = 所有购买的美元投入之和
累计购买 BTC = 所有购买 receivedSats 之和 / 100,000,000
累计损耗 BTC = 所有转移 (amountSats − receivedSats) 之和 / 100,000,000
总持有 BTC = 累计购买 BTC − 累计损耗 BTC = 各账户余额之和
综合成本 $/BTC = 累计投入美元 / 总持有 BTC
当前市值 = 总持有 BTC × BTC 美元市价
总盈亏 = 当前市值 − 累计投入美元
总盈亏率 = (总盈亏 / 累计投入美元) × 100%
```

BTC 使用 Int64 satoshi，现金与汇率使用 Foundation Decimal，美元换算保留十二位小数；JSON 以十进制字符串保存金额和汇率，显示舍入不改原值。零持有时成本、零投入时盈亏率显示「—」。记录按时间、sequence、UUID 重放；`calculate(..., asOf:)` 仅纳入截止时刻已发生的事件，`history` 提供逐事件状态及阶梯成本线。编辑、删除、导入均验证完整历史。

## 迁移与原始备份

schema 5 为美元账本。schema 4 原购买 / 转移的 ID、时间、账户 UUID、BTC 和原人民币金额保留；旧人民币行情缓存丢弃，不能改标签当成美元行情。旧购买在可靠历史汇率全部取得后一次提交换算；失败时原始信息仍完整保存。

schema 1–3 的旧字段只由私有迁移读取结构识别，不参与新账本运行：

- 原人民币购买保留净到账 BTC，投入为原 `amountCNY + feeCNY`，不重复扣 BTC 费用。
- 原转移保留转出、到账与账户；无法归属购买的额外成本进入报告。
- 无调整或卖出干扰、起始中间余额为零的一对一资金链可合并为购买。非末尾链须全部用尽；末尾唯一购买剩余中间资金按转换成本计入该次购买。
- 多笔资金、分批购买、卖出、独立费用、余额调整及来源不明等歧义不猜造；报告注明原因，不能借此猜造后续转移来源。

保留可靠来源映射；能确定的账户命名为欧易 / 自有钱包，其他必要旧账户保留。读取旧账本不立即改写；首次保存前保留原始字节到 `ledger.before-upgrade-vN-UUID.json`。导入旧 JSON 也独立保留来源。目录权限 0700、文件 0600，读取失败保留原文件，外部修改冲突拒绝覆盖。JSON 可完整恢复，CSV 供查看。
